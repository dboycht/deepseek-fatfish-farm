# 记忆系统

目标只有两条：

1. **记得住**——用户几天前发过的图、说过的话，在相关话题出现时能被翻出来，并能回到原话。
2. **足够小**——一条对话、一段相处，压缩后以 KB 计；记忆库有上限，超了自动归档。

## 文件结构

```
<pond>/<fishId>/
├── fish.json                 档案（明文，方便人看）
├── chats/index.json          会话索引（明文，列表秒开）
├── chats/<chatId>.json.gz    会话正文
├── memory/cards.json.gz      记忆卡片
├── memory/state.json         每段对话蒸馏到哪条消息
└── media/index.json.gz       图片索引（含英文描述）
    media/<id>_t.jpg          缩略图（最长边 768，JPEG 84）
    media/<id>.<ext>          原图；>2.5MB 时只留 1600px JPEG
```

所有 gzip 都是 **level 9**，写入走「临时文件 + rename」的原子写，断电不会留下半截文件。

## 卡片格式

```json
{
  "v": 1,
  "cards": [
    {
      "id": "a1b2c3d4e5",
      "t": 1792653417778,
      "k": "event",
      "x": "User sent a photo of a bowl of white rice at night; they were pulling an all-nighter on a physics report.",
      "tags": ["rice", "photo", "physics", "late-night"],
      "src": ["msgA00000003"],
      "img": ["medrice00001"],
      "s": 8,
      "hit": 2,
      "last": 1792739817778
    }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `k` | `fact` 事实 / `event` 事件 / `pref` 喜好 / `person` 人物 / `promise` 约定 / `mood` 心情 |
| `x` | **英文**压缩描述（≤ 200 字符，第三人称、具体、过去时） |
| `tags` | 3~6 个检索关键词（中英都可） |
| `src` | 来源消息 id，用于「回到原话」 |
| `img` | 关联图片 id，用于引用时展示原图 |
| `s` | 重要度 0..9 |
| `hit` / `last` | 被回忆次数 / 最近一次，用于避免反复引用同一张卡 |
| `pin` | 用户钉选，检索加权 0.25 |
| `arch` | 归档卡：由多张旧卡压缩而来 |

> 为什么用英文？同样语义下英文 token 与字节都更省，且主流模型对英文记忆的检索式提示更稳。
> 用户在记忆面板里看到的也是英文原文——这是刻意的「压缩记忆」而非聊天记录。

## 自动蒸馏

触发：每积累 `memory.every` 条新消息（默认 6），或手动点「回味」。

1. 从上次水位线（`state.json` 的 `upTo`）之后取新消息，拼成 `#i [U|A date] 文本 (picture: caption)`。
2. 有 API：让模型输出严格 JSON：
   ```json
   {"cards":[{"k":"event","x":"...","tags":["..."],"s":7,"m":[2,3]}]}
   ```
   提示词要求：最多 3 张；只留长期有效信息；跳过寒暄与密钥；每张必须能独立成立。
3. 无 API：正则兜底（身份、喜欢/讨厌、所在地、计划、提醒、图片事件、兜底事件）。
4. 去重（同 kind 且去标点后文本相同则跳过）→ 追加写盘 → 更新水位线 → 检查是否需要归档。
5. 每张新卡给肥鱼 +6~9 exp，饿度略微上升（「想事情也费饭」）。

## 有界压缩

`cards` 数量超过 `memory.maxCards`（默认 400）时：

- 取最旧的 8~16 张非归档卡；
- 有模型时合成一张 `arch` 卡（≤200 字符，保留人名、偏好、约定），否则拼接截断；
- 合并 tags / src / img，`t` 取最旧，`s` 取均值；
- 删除被合并的卡。归档卡仍可被检索，只是排名略降。

这样记忆文件的体积**有上界**，不会随时间无限增长。

## 检索打分

`src/shared/recall.ts`（纯函数，有单测）：

1. 分词：英文按单词（≥2 字符），中文按**二元组**（`白米饭` → `白米`、`米饭`），去重。
2. 相关度：命中词的 IDF 和 ÷ 命中词的 IDF 总和（只对「语料里出现过」的词归一化，
   避免长中文句子的噪声词稀释分数）。
3. 综合分：
   ```
   0.62 * 相关度
 + 0.18 * 时间衰减（半衰期 90 天）
 + 0.14 * 重要度（s/9）
 + 0.25 * 钉选
 + 0.35 * 图片线索（查询含「图/照片/那张」且卡片有 img）
 - 0.06 * 归档
 - 0.05 * min(hit, 6)
   ```
4. 阈值：`score ≥ 0.2` 且 `相关度 > 0.12`，取前 `memory.recall` 条（默认 6）。

## 引用回链

- 检索结果按 `M1..Mn` 编号写进系统提示词，附日期、类型、是否有图。
- 要求模型在真正用到某条时写 `<cite id="M1"/>`，不许编造编号。
- 主进程解析出锚点 → 映射成卡片 id 存进消息的 `cite` 字段。
- 渲染端把 `<cite>` 变成 📎 徽章（显示卡片日期）；点开是卡片正文 + 原图 + 「回到原话」。
- 「回到原话」会扫描该鱼的所有会话，切到对应会话并滚动/高亮那条消息。

## 导入导出

| 扩展名 | 内容 | 用途 |
| --- | --- | --- |
| `.fatfish` | 档案 + 全部会话 + 全部卡片 + 全部图片 + 蒸馏水位 | 整只鱼搬家/备份 |
| `.fatmem` | 卡片 + 被引用到的会话片段 + 被引用到的图 + 水位 | 只搬记忆，合并进现有鱼 |

两者都是「JSON → gzip → 单文件」，不含 API Key。导入整只鱼会新建一只（换新 id，不覆盖），
导入记忆会按文本去重后合并。

## 体积实测

自检（`node scripts/selftest.mjs`）生成的样本：

- 8 条消息（约 200 字中文）
- → 3 张卡片
- → `cards.json.gz` 525 字节
- → 整只鱼导出 1,188 字节

也就是说，一次普通聊天留下的长期记忆大约是**几百字节**；图片按需单独存。

## 边界与隐私

- 记忆只存在本地鱼塘目录，不上传；请求只发往你配置的 API。
- 记忆卡片会包含对话中的事实与偏好，请像对待聊天记录一样对待鱼塘文件夹。
- 导出前请确认包里没有你不想带走的内容（文件本身是二进制 gzip，可用任何 gzip 工具解开检查）。
- 没有加密：磁盘上的卡片是 gzip 明文。需要加密请用 BitLocker 等整盘方案。
